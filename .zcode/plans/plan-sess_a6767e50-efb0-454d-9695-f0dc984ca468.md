# 修复 DSH 会话中"启用团队"失败（sessionId 断链假象）

## 根因（已实证，非猜测）

宿主错误日志 `C:\Users\10042\.dsh\dsh-web-restart.log.err`：

```
[dsh-weave] automatic host wiring failed: Error: cannot get property "webServer" without inject
    at registerWeaveRpc (K:/work/project/weave/dist/plugins/weave/rpc.js:393)
```

`rpc.ts:501`（HTTP fallback 注册处）直接读 `(context as any)?.webServer` —— cordis 规定服务必须经 inject 访问，属性 getter 直接抛错。该异常从 `index.ts:209` 一路抛到 `index.ts:239` 的外层 catch 被 `console.warn` 吞掉，**catch 之后的代码全部没执行**：

- `agent/pre-step` 钩子（index.ts:225-234）没注册 → 会话里发"启用团队X"无任何响应；
- `registerWeaveHost`（index.ts:213）没执行 → weave_* 工具全没注册；
- HTTP `POST /dsh-weave/*` 路由没注册 → Web 面板绑团队时 RPC 失败（"消息传递有问题"）。

宿主侧**没有问题**：`conversation.view` 槽位由框架标准注入 `sessionId` prop（`SessionStandardProps`），`agent/pre-step` 的 `payload.agent.id` 就是会话 id。**用户/模型从头到尾都不需要手动提供会话 id**——只是插件接线崩了导致看起来"缺 sessionId"。

（注：`delegation-service.ts` 的未提交改动只是往 prompt 加提示文本，与本次故障无关，保留不动。）

## 修复内容

### 1. 根因修复 — `src/plugins/weave/rpc.ts` `registerWeaveRpc`（L499-529）
HTTP fallback 的 `webServer` 获取改为与 L494 `connection` 同构的延迟注入模式：

```ts
runtime.inject?.(['webServer'], (scoped) => {
  const ws = scoped.webServer
  if (ws?.register) { ws.register({ kind: 'prefix', path: WEAVE_RPC_CHANNEL, handler: ... }) }
})
```

不再直接读属性，永不抛错；headless 无 webServer 时回调不触发、自然降级。

### 2. 加固 — `src/plugins/weave/index.ts`（L209-237）wiring 解耦
同一类"服务访问抛错连坐杀死全部接线"的 bug 已是第二次（上次是 `agents`，commit 7d4b832）。重构为三段独立容错：

1. **pre-step 钩子最先注册**（只依赖已构造好的 `deps.teamManager`，无外部服务依赖），单独 try/catch；
2. `registerWeaveRpc` 单独 try/catch；
3. `registerWeaveHost` 单独 try/catch。

每段失败输出具体化的 warn（如 `[dsh-weave] rpc registration failed:`），传输层故障不再连坐杀掉会话控制通道和工具注册。

### 3. 消除假会话 id — `weave_team_switch` 缺省解析
`cli-mcp.ts:129` 缺 `session_id` 时回落字面量 `'cli-session'`，绑定写进假 id，真实会话查不到——这正是"要先知道会话 id 才能继续"的另一来源。改为：

- `host-wiring.ts:217` 的 `execute: (args, exec) => ...` 接收 exec（工具框架会传，planTasks 已是此模式）；
- 缺省时经 `resolveHostSessionId(exec.agent)`（复用 planner.ts:332 + `agentsRegistry` 血缘回溯）解析真实宿主会话 id；
- 解析不到且无 exec（纯 CLI 场景）才保留 `'cli-session'`。

优先级：显式 `session_id` > exec 回溯 > CLI 兜底。
