# Weave 重构：会话即团队 · 队长调度模式

目标：①删除任务中心与会话管理页，运行时信息收敛到会话视图；②任务与会话绑定，面板显示成员实时状态与本会话任务图；③废除命令式下发与硬编码流水线，改为「当前会话=队长」模型动态规划、插件按依赖自动调度执行并汇总。

## 第一步：技术验证（spike）

**获取当前会话 id**（面板按会话过滤的前提）：检查 DSH 运行时安装里的 `@deepseek-ai/dsh-client-ui-slots`（复用 `scripts/env-check.mjs` 的 DSH 根探测方式），确认 `conversation.view` 槽位组件渲染时宿主是否传入 session 上下文 props。
- 能拿到 → 直接透传给新面板组件；
- 拿不到 → 兜底：pre-step 钩子已在每条消息可见 `agent.id`(sessionId)，服务端加内存级「最近活跃会话」注册表，新增 RPC `session/current` 返回最近活跃会话；面板顶部展示并可从绑定列表切换查看。两种结果都不阻塞后续开发，客户端按统一 props 入口封装。

## 服务端改造

### 1. 新增队长规划工具 `weave_plan_tasks`
文件：`src/plugins/weave/host-wiring.ts`（工具定义）、新建 `src/plugins/weave/planner.ts`（校验+落库）。

输入：`{ goal?, tasks: [{subject, description, assignee:<角色id>, depends_on?: string[]}] }`。
- 校验：会话已绑定团队（优先级链复用 `TeamManager.selectTeam`）、assignee 是该团队角色、depends_on 引用合法且无环。
- 落库：经 SingleWriterQueue 写入 dags/edges/tasks 三表，`session_id`=当前会话、状态 WAITING/BLOCKED（有未完成依赖），序列号沿用 `task_sequences` 分配器。
- 返回 DAG 摘要给队长模型用于向用户转述，随后自动触发调度器。
- 同时删除命令式下发：MCP 工具 `weave_submit_task`（host-wiring）、CLI `task submit` 子命令（cli-mcp.ts `WeaveCli.run/#dispatch`）、Web RPC `task/create`（web/query-service.ts）。其余反馈类命令（revise/accept/retry/skip/cancel/reopen/status/dag）保留——它们正好成为对真实落库任务的操作入口。

### 2. DAG 依赖调度器（替代 SequentialSessionDelegator 模板流水线）
新建 `src/plugins/weave/scheduler.ts`，复用 `DelegationService.executeTask`（唯一执行出口不变）、知识注入、fallback 重试、ProcessLimiter：
- 就绪判定：WAITING 且全部依赖处于成功终态 → 可派发；多任务并行时受角色 `max_concurrent_tasks` + 执行器限流约束。
- 输出链：上游产物作为 upstreamOutputs 注入下游 prompt（同现有机制）；失败重试一次后置 FAILED 并用现有 `propagateFailure` 把下游置 SKIPPED。
- 全程回写真实状态（修复当前"执行的内存态 vs 落库的不执行"两条轨割裂问题）；每个阶段开始/完成/失败通过现有 `notifySession` 向会话追加插件通知，DAG 整体结束时发汇总通知引导队长做最终总结输出。
- 取消联动：维护 taskId→AbortController 注册表，UI/MCP 的 `task/action cancel` 触发真实中止，下游走 SKIPPED 传播。
- 同会话允许存在多个 DAG（按创建时间排列，靠并发限制仲裁），v1 不做互斥。

### 3. pre-step 钩子瘦身（session-delegation.ts）
- 保留自然语言团队启停短句解析（启用/关闭XX团队 → team_bindings 读写 + reject）。
- 删除「matcher 匹配难度 → dag_templates 展开阶段 → 顺序执行」的自动触发链。
- 若钩子支持向本轮上下文注入文本，则附加一段简短的队长指引（你已绑定某团队、成员列表、多步目标请调用 weave_plan_tasks）；不支持则仅靠工具描述承载（实现时确认）。

### 4. 成员运行时状态
新建内存注册表（随 scheduler 维护）：session→各角色 {taskId, startedAt}。新增 RPC `session/status {sessionId}` 返回成员数组：`idle | 执行中(subject) | 冷却中` + 最近一次结果（取本会话最新 DAG 内该角色任务的持久化状态派生）。

### 5. 查询接口补会话维度
`web/query-service.ts`：`task/list` 增加 `sessionId` 过滤参数；`session/bindings`、`session/revisions`、`team/*` 保持不变；新增 `session/status`、（兜底用）`session/current`。

## 客户端改造（src/client/index.ts，保持单文件无打包器约定）

### 6. 新会话视图面板 WeaveSessionPanel（替换 WeaveSessionDag，仍挂 conversation.view 槽位）
自上而下四段：
1. **团队头**：本会话绑定团队名；未绑定时显示引导「发送 启用<团队名>，或在下方选择」，内嵌团队下拉选择（调既有 `session/team-selection/set`）——接管原会话管理页的绑定职责。
2. **成员卡片区**：每角色一张卡：姓名(角色)·执行器/模型 + 状态徽标（空闲/执行中+当前任务名/熔断冷却），数据来自 `snapshot` + 新 `session/status`。
3. **本会话任务 DAG**：`task/list {sessionId}` → 最新 DAG → 复用 `DagGraph` 渲染；节点点开显示详情与快捷动作（验收/返工/取消/重试/跳过，沿用 TASK_ACTIONS_BY_STATUS + `task/action`）——任务中心删除后这是唯一操作入口。
4. 保留 5s 自动刷新 + 手动刷新按钮的模式。

### 7. 控制台收缩
- ROUTES 删除 `tasks`、`sessions` 两项，Route 类型/页面映射/`TasksPage`/`SessionsPage` 函数整体删除（约减 400 行）。
- 原会话管理页的修订记录（session/revisions）并入总览页一个轻量区块。
- 「命令手册」页移除 task submit 相关条目，补充队长模式用法说明。

## 文档与测试

- README §5 改写为队长模式交互说明（下发只有对话一条路、面板职责、7 页控制台）。
- 单测（vitest，基于既有 fixtures/mock-subagents.ts）：planner 校验（未知角色/成环拒绝）、scheduler（依赖门控/并行限流/上游链注/失败传播落库/取消中止）、query-service sessionId 过滤与 session/status。

## 明确不做
- 不引入成员间 inbox 消息总线（agents team 只借形态：队长-成员-带依赖的任务-状态汇总；通信仍由插件单向编排+通知回灌）。
- 不改动任务14态状态机、知识库、导入、审计等既有模块的行为。
