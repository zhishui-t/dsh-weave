## 1. 设计文档

### 1.1 目标

实现 Weave 的完整独立能力：

1. 项目代码图谱（Graphify）
2. 知识图谱（Graphify 替换现有轻量 `[[双链]]`，保留审核生命周期）
3. Obsidian 真实 Vault 集成（生成 / 打开 / 回索引 / 冲突保护）
4. AnyDoc 独立文档转换（复用现有转换能力，独立状态机）
5. 以上能力均不依赖 Weave 团队 / 队长 / 任务调度

### 2.2 GraphService 接口（已有）

| 方法 | 说明 |
| --- | --- |
| `build()` | 改为 `extract + flows build`，生成 graph.json 与 flows.json |
| `query(question, { budget, dfs })` | 图谱语义查询 |
| `path(source, target)` | 两点最短路径 |
| `explain(node)` | 节点解释 |
| `affectedFlows(files)` | 改动文件影响面（JSON） |

| `hasGraph()` | 是否已构建 |

### 2.3 RPC 契约

#### 代码图谱（code/*）

| 端点 | 入参 | 返回 |
| --- | --- | --- |
| `code/build` | `{}` | `{ graphPath, flowsPath }`（构建/刷新图谱与执行流） |
| `code/graph` | `{}` | `{ nodeCount, edgeCount, communityCount, graphPath, builtAt }` |
| `code/path` | `source`, `target` | `{ path: string }` |
| `code/explain` | `node` | `{ text: string }` |
| `code/affected` | `files: string[]` | `AffectedFlowsResult` |
| `code/flows` | `limit?` | `GraphFlow[]` |
| `code/flows/get` | `id` | `GraphFlow` |

错误码：未构建 → `configuration_error`；CLI 非零 → `graph_execution_failed`；解析失败 → `internal`；节点不存在 → `invalid_argument`。

#### 知识图谱（knowledge/* Graphify 版）

| 端点 | 入参 | 返回 |
| --- | --- | --- |
| `knowledge/build` | `{}` | `{ graphPath }`（对 `~/.dsh/knowledge` 构建 Graphify 图） |
| `knowledge/graph` | `status?`, `layer?`, `project?`, `limit?` | `{ nodes, links, communities, counts }`（Graphify 结果，映射现有 `KnowledgeGraphResult`） |
| `knowledge/query` | `question`, `budget?` | `{ text: string }` |
| `knowledge/path` | `source`, `target` | `{ path: string }` |
| `knowledge/explain` | `node` | `{ text: string }` |

保留审核生命周期：candidate/active/deprecated/superseded 过滤与 approve/reject 入口不变，Graphify 只替换图谱渲染与查询。

#### Obsidian（obsidian/*）

| 端点 | 入参 | 返回 |
| --- | --- | --- |
| `obsidian/generate` | `{ vaultPath? }` | `{ generated: number, updated: number, vaultPath }` |
| `obsidian/open` | `{ vaultPath? }` | `{ opened: true }`（浏览器拼 `obsidian://open?path=...`） |
| `obsidian/reindex` | `{ vaultPath? }` | `{ reindexed: true, entries: number }` |
| `obsidian/status` | `{ vaultPath? }` | `{ exists, vaultPath, lastGeneratedAt, conflictCount }` |

错误码：
- Vault 不存在/不可写 → `configuration_error`
- 指纹/同步失败 → `internal`
- 文件已被用户修改且无法安全合并 → `conflict_detected`
- CLI 用法错误 → `invalid_argument`

CLI 命令（`/weave obsidian ...`）：
```text
/weave obsidian generate [--vault <path>]
/weave obsidian open [--vault <path>]
/weave obsidian reindex [--vault <path>]
/weave obsidian status [--vault <path>]
```

#### AnyDoc 独立转换（document/*）

| 端点 | 入参 | 返回 |
| --- | --- | --- |
| `document/convert` | `{ filename, dataBase64 }` 或 `{ path }` | `{ jobId, status }` |
| `document/preview` | `{ jobId }` | `{ markdown, title, warnings }` |
| `document/status` | `{ jobId }` | `{ jobId, status, markdown?, title?, warnings?, error? }` |

明确方案：
- 复用 `import-pipeline.ts` 的 `AnyDocConverterAdapter` 与 `WHITELIST_EXTENSIONS`；
- 独立 job 存储在 `state_dir/convert-jobs.json`，不复用 ImportMeta；
- 控制台走 `dataBase64 + filename`；CLI 走 `path`；
- 限制扩展名白名单、大小上限（默认 50MB）、UTF-8 输出；
- 服务端路径模式必须限定在授权目录内，禁止任意文件读取。

错误码：
- 白名单外扩展名 / 超大小 / base64 解码失败 → `invalid_argument`
- 目录逃逸、非法路径 → `invalid_argument`
- 转换失败 → `document_conversion_failed`
- job 不存在 / 已过期 → `configuration_error`

### 2.5 控制台 UI

- 新增路由：`代码图谱`、`文档转换`；知识库页保留在现有路由但内部图谱区域替换。
- 代码图谱页：构建/刷新按钮，节点/社区/影响面视图，未构建时显示空态并提供构建入口。
- 知识库页：Graphify 图谱渲染 + 生命周期过滤 + approve/reject 入口保留。
- 文档转换页：上传/转换/预览/状态。
- Obsidian 页：生成/刷新、打开、回索引、冲突状态展示。
- UI 交付必须附 Playwright 无头自验截图与 e2e mock 端点。

### 2.6 Obsidian 数据与冲突矩阵

- 默认路径：`~/.dsh/obsidian`；可配置项目内 `obsidian/`。
- 同步方向：Weave 知识 active/candidate → Vault Markdown；用户手动编辑优先。
- 冲突策略：

| 场景 | 行为 |
| --- | --- |
| Weave 更新，用户未改 | 覆盖 |
| Weave 更新，用户已改 | 保留用户修改，记录 conflict |
| 双方都改 | 保留用户修改，生成 Weave 侧备份，记录 conflict |
| 用户删除 | 不重新生成该文件，记录 tombstone |
| 首次生成 | 全量生成；已有文件不覆盖 |
| 用户重命名 | 保留用户命名，生成新条目，记录 alias |
| 二进制附件 | 仅同步 frontmatter 与链接，不覆盖二进制内容 |
| 增量刷新 | 只重算变更条目，未变更文件不重写，避免 mtime churn |

- frontmatter 规范沿用 KnowledgeFrontmatter。
- 指纹存储：`<vault>/<project>/.weave-fingerprint.json`，记录文件 hash/mtime。

### 4.2 负向用例（每组写清楚前置条件→操作→期望）

**代码图谱（code/*）**

| # | 前置 | 操作 | 期望 |
