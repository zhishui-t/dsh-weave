# Weave 图谱与独立能力完整版设计

> 状态：设计讨论定稿，待实施
> 范围：代码图谱、知识图谱、Obsidian、AnyDoc 独立转换能力
> 原则：**不分 P0/P1，一次性交付完整能力；图谱与文档转换独立于 Weave 团队**

---

## 1. 目标

Weave 将提供一套完整、独立、可脱离团队使用的能力：

- 项目代码图谱
- 知识图谱（替换现有轻量版）
- Obsidian 真实 Vault 能力
- AnyDoc 独立文档转换能力

这些能力可以作为：

- Weave 控制台功能
- 独立 RPC / CLI / MCP
- DSH 子代理或 ZCode 执行器可调用的工具
- 不依赖 Weave 小队 / 队长 / 任务调度

## 4. 项目代码图谱

### 4.1 数据

```text
<项目根>/.graphify/
├── graph.json
├── GRAPH_REPORT.md
└── ...
```

- 数据放在项目目录内
- `.graphify/` 加入 `.gitignore`
- 项目路径由 Weave 配置登记，也可从 DSH 会话 cwd 自动识别

### 4.2 构建

- `pnpm code:scan`
- 首次查询自动 build
- 手动触发 `weave_graph_build`
- 可配置 watch 自动更新

### 4.3 能力

- 文件/目录过滤
- 节点详情
- 上下游调用链
- 两点最短路径
- 改动影响面
- 执行流分析

### 4.4 RPC

| 端点 | 说明 |
| --- | --- |
| `code/graph` | 获取图谱数据 |
| `code/path` | 两点最短路径 |
| `code/explain` | 解释节点 |
| `code/affected` | 改动文件影响面 |
| `code/flows` | 执行流分析 |

### 4.5 工具

| 工具 | 说明 |
| --- | --- |
| `weave_graph_build` | 构建/更新图谱 |
| `weave_graph_query` | 图谱查询 |
| `weave_graph_path` | 最短路径 |
| `weave_graph_explain` | 节点解释 |
| `weave_graph_affected` | 影响面 |

## 5. 知识图谱

### 5.1 目标

用 Graphify 替换现有轻量 `[[双链]]` 预览。

### 5.2 数据源

- `~/.dsh/knowledge`
- 项目知识/文档目录

### 5.3 保留 Weave 知识生命周期

- candidate → active
- active → deprecated / superseded
- reject：candidate → deprecated
- 审核流程不变

### 5.4 能力

- 知识图谱页
- `knowledge/query`
- `knowledge/path`
- `knowledge/explain`
- 社区聚类
- 知识语义问答

### 5.5 执行器使用

- DSH 子代理：`weave_graph_*`
- ZCode / ACP：Graphify MCP

## 6. Obsidian 完整版

### 6.1 现状问题

当前 Obsidian 只是“打开入口”，Vault 可能为空，无生成、无同步、无索引。

### 6.2 目标

- 一键生成 / 刷新 Vault
- Markdown + frontmatter 天然兼容
- 生成 `[[双链]]`、wiki、图谱页面
- Obsidian 打开
- Obsidian 手动编辑后重新索引
- 冲突保护：不覆盖用户手动修改

### 6.3 默认路径

```text
~/.dsh/obsidian
```

或项目内：

```text
<项目根>/obsidian
```

可配置。

### 6.4 行为

| 行为 | 说明 |
| --- | --- |
| 生成 | Weave → Obsidian，创建/更新 Markdown 与图谱页 |
| 打开 | `obsidian://open?path=...` |
| 回索引 | Obsidian 手动修改后重新扫描/索引 |
| 冲突保护 | 对比文件指纹；外部修改优先保留，不静默覆盖 |

## 7. AnyDoc 独立文档转换

### 7.1 独立模块

```text
src/plugins/weave/convert/
├── document-converter.ts
├── cli.ts
└── mcp.ts
```

### 7.2 能力

- 任意文档 → Markdown
- 支持 doc/docx/odt/rtf/epub/pdf/ppt/pptx/xls/xlsx/csv
- 转换预览
- 转换结果缓存
- 不依赖团队、不依赖知识导入流程

### 7.3 入口

| 入口 | 说明 |
| --- | --- |
| RPC | `document/convert`、`document/preview`、`document/status` |
| CLI | `/weave document convert <file>` |
| 控制台 | 独立文档转换能力 |
| MCP | 可选，给执行器用 |
| DSH 子代理 | `weave_document_convert` |

### 7.4 与知识导入的关系

知识导入作为 AnyDoc 的消费方，但 AnyDoc 能力本身独立。

## 8. ZCode / DSH 子代理如何用

### 8.1 ZCode（ACP 执行器）

通过 Graphify MCP：

```text
graphify query
graphify path
graphify explain
graphify tree
graphify flows
graphify affected-flows
```

在 zcode provider 的 `mcp_servers` 中挂载：

```json
{
  "name": "zcode",
  "command": "node",
  "args": [".../zcode-acp-server/dist/index.js"],
  "mcp_servers": [
    {
      "name": "graphify",
      "command": "graphify",
      "args": ["serve", "<项目根>/.graphify/graph.json"]
    }
  ]
}
```

### 8.2 DSH 子代理

通过 Weave 工具：

```text
weave_graph_query
weave_graph_path
weave_graph_explain
weave_graph_affected
weave_graph_build
weave_document_convert
```

## 9. 与团队的独立性

- 代码图谱、知识图谱、文档转换是**项目级能力**
- 不依赖团队配置
- 不依赖会话绑定团队
- 不依赖队长/角色/任务
- 不使用 Weave 小队时也可通过 CLI / MCP / 控制台使用
- Weave 团队只是可选增强入口
